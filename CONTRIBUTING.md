# Contributing to HireSense AI

Thanks for helping improve HireSense AI.

## Before you start

- Read the project README and understand the current milestone.
- Keep changes focused on one feature, fix, or documentation improvement.
- Do not commit secrets, credentials, local databases, uploaded resumes, or generated model artifacts.
- Prefer small pull requests that are easy to review.

## Development workflow

1. Fork the repository.
2. Create a focused branch from `main`.
3. Create or update tests for behavior you change.
4. Run the relevant checks locally.
5. Open a pull request with a concise description of the change.

## Pull request checklist

- [ ] The change has a clear purpose.
- [ ] Existing behavior is preserved unless intentionally changed.
- [ ] Tests or validation steps are included where applicable.
- [ ] Documentation is updated when behavior or setup changes.
- [ ] No secrets or local-only files are included.

## Commit style

Use a short imperative subject, for example:

`docs: clarify local setup`

Keep unrelated changes in separate commits or pull requests.
